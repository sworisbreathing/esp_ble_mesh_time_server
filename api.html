Structures and Types Documentation

struct esp_ble_mesh_time_server_config_t

BLE Mesh time server configuration.

Variables:

  • nvs_handle_t nvs_handle
    NVS Handle for settings persistence.
    When time server persistence is enabled via CONFIG_ESP_BLE_MESH_TIME_SETTINGS, this must be a properly initialized handle which must remain valid during the lifetime of the BLE Mesh device.

  • esp_ble_mesh_time_srv_t * time_server
    Pointer to the BLE Mesh time server.
    This pointer must remain valid during the lifetime of the BLE Mesh device. Shall not be set to NULL. State property must not be NULL and must be shared with time_setup_server.

  • esp_ble_mesh_time_setup_srv_t * time_setup_server
    Pointer to the BLE Mesh time setup server.
    This pointer must remain valid during the lifetime of the BLE Mesh device. Shall not be set to NULL. State property must not be NULL and must be shared with time_server.

function ble_mesh_time_init

Initialises BLE Mesh Time functionality.

esp_err_t ble_mesh_time_init (
    esp_ble_mesh_time_server_config_t config
)

Note:

This API needs to be called after BLE Mesh Time callbacks are registered and BLE Mesh is initialized.

The time server, time setup server, and state must be defined, and the state must be set on both the time server and time setup server.

Parameters:

  • config The time server configuration. Its contents must remain valid for the life of the BLE Mesh device, however the configuration itself need only remain valid until this call completes.

Returns:

  • ESP_OK: success
  • ESP_ERR_INVALID_ARG if time_server or time_setup_server are NULL or their state is not properly bound
  • error codes returned by nvs_get_blob
  • error codes returned by esp_timer_create

define DEFAULT_TAI_UTC_OFFSET

The TAI-UTC delta as of 31 December, 2016.

#define DEFAULT_TAI_UTC_OFFSET 37

Note:

The BIPM voted in 2026 to replace leap seconds with leap hours. Leap hours are not expected to be added for several centuries.
